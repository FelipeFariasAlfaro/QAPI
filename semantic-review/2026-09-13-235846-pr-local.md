# Recuperación de QAPI WebviewView tras reinstalación (v3)

La inicialización, el orden respecto de MCP, la restauración de UI y el lifecycle corrigen los tres hallazgos previos. Queda una exposición nueva en la restauración: el borrador MCP completo se guarda en el estado del webview aunque su `env` puede contener credenciales. Las API keys del proveedor sí quedan fuera del estado local.

**Watch for:** **[MEDIA, confirmed]** credenciales incluidas en `mcpDraft` se persisten en texto plano mediante `vscode.setState`.

**Verdict**: NEEDS_CHANGES

## High-level view

El handshake queda coalescido por instancia y `init` se entrega antes de `validateMcpConfig`; los borradores no se reemplazan durante reintentos y los listeners se liberan al disponer la vista. La restauración de MCP rompe, sin embargo, la condición de no persistir API keys cuando el JSON usa `env` para tokens o credenciales.

## Secretos de `env` incluidos en la restauración MCP

**[MEDIA, confirmed]** `src/webview/main.ts:77-80` persiste `mcpDraft` sin filtrado y lo actualiza con todo el contenido del editor en `src/webview/main.ts:993-994`. El contrato MCP acepta valores arbitrarios de `env` (`src/mcp.ts:62-71`) y los entrega al proceso (`src/mcpRuntime.ts:62-65`), por lo que configuraciones habituales con `API_KEY`, tokens o contraseñas quedan almacenadas en texto plano dentro del estado del webview. La exclusión explícita de `providerDraft.apiKey` no cubre esas credenciales; la restauración debe separar secretos hacia `SecretStorage` o persistir una versión redactada que no pueda sobrescribirlos al hidratar.

</details>
